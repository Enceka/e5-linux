# TF 单根安装与电脑更新（2026-10-14）

适用于公共 E5、T551M、VIPME M8 打包流程。原先约 2 GiB 的初装根分区、
预留未分配空间并轮换新根的 TF 更新方式停止用于新版安装和更新。

## 安装

- 电脑 EXE/Python 和原生 Magisk 共用 `android-tf.sh`。
- 排除 Android 的内部 eMMC，确认只有一张 TF，检查只读状态和容量。
- 优先已有第一分区；没有任何分区才使用整卡。存在其他分区而缺少第一分区时拒绝，避免误覆盖。
- 不修改分区表；只清空选中的目标。其他分区不会被写入。
- 本机固件转换和载荷上传完成、Android 释放所有卡挂载及映射后，才写入镜像。
- 使用包内新版 ext4 工具检查、扩容到目标全部容量，验证 superblock 的实际块数。
- 镜像与固件回读验证通过后，才写启动镜像和修改启动槽位。首次安装不自动重启。

“全部容量”指所选分区的容量。原本只有 2 GiB 的第一分区不会自动跨越后续分区或空闲区；
若需要重新规划旧卡，应先备份再自行建立占满卡的第一分区。
E5 的根仍为直接挂载的 ext4，而 MU300 为分区内目录；这里对齐容量使用与安装/更新入口，
不改变 E5 现有运行根结构。

## 更新

统一通过电脑 `OpenWrt-Installer.exe` 的更新选项或 `launchers/update-openwrt`。
普通设备端 TF 镜像更新入口拒绝执行并提示使用电脑安装器，不再分配备用根。

电脑经 SSH 上传并校验，设备保存配置及固件；新 boot 校验成功后才发布离线更新请求。
initramfs 校验卡 CID、SD 类型、目标容量、机型、根标记和载荷哈希，将全部载荷复制到内存，
卸载原根后再写入原目标、回读、扩回原容量并恢复配置与本机固件，最后重启。
不改 GPT，不写 Android userdata，不需要额外 OTA 分区。

实机 E5 使用 `CONFIG_CMDLINE_FORCE`，boot 头标志可能被忽略。因此 TF 更新请求直接在
initramfs 的 SD 根探测中发现，不依赖 boot 头传参，不增加运行时轮询。

与原有设置迁移范围一致，保留密码、SSH 密钥、热点/APN、短信、流量、屏幕设置等配置；
自行安装的软件包与备份范围外的用户文件不迁移。更新前自行备份重要资料。
单根系统没有第二份 TF 根可自动回退；写入期间保持供电。

旧多根卡仍可启动。电脑更新只操作当前根、保留原 `sd-gen`/系统标识，不合并或删除旧分区。
旧包缺少 `tf_update` 能力标记时，新电脑更新器在写 boot 前拒绝 TF 更新，需要重新构建完整包。

## 验证范围

- 独立稀疏文件验证第一分区/整卡选择、缺失第一分区与 eMMC/只读卡拒绝。
- 实际 ext4 工具将 64 MiB 测试镜像扩至 64 GiB，校验实际容量及原文件内容。
- 离线更新回归覆盖 TF 分区/无分区整卡、原独立内置分区、容量/设置/固件保持，
  以及错误 CID、非 SD 设备、损坏载荷、内存不足、仍挂载、写入/扩容/回读失败。
- 三机型共用打包校验和安装器诊断回归。

这是源码和隔离测试结果；尚未重建三机型完整发行包，也未执行 TF 实物刷入。
