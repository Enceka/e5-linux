# Android 安装工具统一携带 BusyBox

日期：2026-10-17，适用于 E5、T551M、M8 公共安装流程。

## 原因与修改

OpenWrt 的启动镜像原本就携带独立 BusyBox；不一致的是 Android 安装入口仍从 Magisk 或 KSU 目录选择工具。现在统一为安装包的 `files/busybox`，直接复用构建启动镜像时传入的同一个静态 ARM64 程序，不再按 root 管理器查找或回退。

- 两个打包入口均复制同一个 BusyBox 输入。构建开始和最终封包阶段检查 ARM64 ELF、程序头及静态链接属性；拒绝缺失、错误架构、动态链接或程序头截断的输入。文件纳入包内摘要清单，ZIP 和解压安装共用。
- 电脑安装先确认机型与 root，再上传至独立的私有临时目录，转为 root 所有，核对摘要、所需 applet 和 standalone ash。通过后 root 安装命令统一在该 BusyBox shell 内执行，不依赖 Android toybox 或管理器 PATH。失败发生在分区安装前。
- ZIP 模块入口及原生 TF worker 使用同一个随包工具；进入 Android 主挂载命名空间的原有方式保持不变。不会安装常驻 Magisk 服务。
- 图形安装器重新绑定设备时清除旧工具状态；利用未分配空间安装的入口也准备同一套工具。正常开机、AT 时序和 NV 不涉及本次更改。

`su` 是取得 Android root 权限的入口，与 BusyBox 不是同一层。原有 root 授权探测保留；去掉的是 Magisk/KSU BusyBox 路径选择和依赖。Android 重置后仍需重新授权 Shell root。
