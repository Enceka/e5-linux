# USB 更新修复：SSH 上传与独立分区更新

## 已确认的故障

Windows 对用户解压出的 `OpenWrt-Installer.exe` 有两条 Public 入站 Block
规则。旧更新器需要设备主动访问电脑临时 HTTP 服务，因而脚本下载就失败，
返回 `Failed to send request: Operation not permitted`。同一台 T551M 通过
Python 的临时 HTTP 服务可正常下载，USB 路由与设备 wget 均正常。
失败发生在任何 boot 写入之前；机器当时的运行时长和独立 e5root 都未改变。

## 公共修复

- 更新器通过 SSH 主动连接设备，二进制流上传并逐项核对 SHA256；密码仅放在
  子进程环境变量，不写文件或命令行。不更改电脑防火墙规则。
- Windows EXE 内置 Paramiko，外部 Python 使用者需安装此依赖。主机公钥保存
  在包的 `backups/ssh-<profile>.known_hosts`，已知公钥变化时拒绝连接。
- 在上传前校验目标机型、实际布局和独立分区容量；旧的不支持独立分区更新的
  boot 包提前拒绝，不能误走 userdata 镜像文件流程。
- TF 和旧 userdata 镜像保留原迁移规则。完整事务通过同一个升级 flock 排他，
  子安装器验证继承的 FD 8，避免父子互相等待或锁释放过早。
- 独立 e5root 保存压缩镜像、本机固件、配置和 ext4 工具；新 boot 写入并
  回读校验后才发布请求。重启后所有载荷先复制到 RAM，校验 CID、分区大小、
  profile、归档和原始镜像长度/校验和，再卸载原分区并写入。
- 不修改 GPT、不挂载加密 userdata。写入后回读镜像，离线扩容到原分区容量，
  恢复设置及固件，保留新版 phone 代码和构建版本，再只读重挂校验恢复的文件。
- 正常开机在已有固件挂载步骤中检查请求，没有请求时不增加分区挂载或轮询。
  三个内核使用 CONFIG_CMDLINE_FORCE，因此更新触发不依赖 boot 头的额外参数。
  新根内的 part-autoboot 支持无法读取 Android data 时选择独立根，并尊重明确
  指定的其他启动目标及 TF 系统登记。

## 验证与限制

实机确认 T551M 的 SSH 登录、256 KiB 二进制上传和 SHA256 回读正常，临时
测试文件已经清理。本轮没有给设备刷写系统。

实际 shell 更新器用普通稀疏文件运行，检查保存密码、中文热点、本机固件、
新版 phone 代码、原分区容量，以及 CID 错误、内存不足、归档损坏、根仍挂载、
写入失败、扩容失败、卸载后内容损坏和无请求启动分支。安装器、缩容、F2FS
修复与 CI 回归通过；成品执行文件另做启动与依赖检查。

独立分区更新是在同一个分区重写，没有 TF 两个系统分区的自动回退能力。
写入阶段需要保持供电；APK 额外安装的软件不迁移。完整实机升级仍需使用
新版安装包执行，不能把上述上传测试当成已经完成实机升级。
