# T551M 最新更改全量核对与补齐

## 发现

此前只热更新事件亮屏的 4 个文件，不能代表同步了所有公共更改。用户要求全量
同步后，从当前源码重建预期程序树：公共 OpenWrt overlay、共享脚本、LuCI
看板、infoscreen、T551M configure-rootfs 的板级文件变换，并对现有第三方
netifd/hostapd/LuCI 文件应用公共补丁。保留用户配置，不能重跑首次安装的网络
和密码初始化，也不能把 M8 听筒走喇叭、低档衰减等元数据搬到 T551M。

核对发现另外 10 个旧版或缺失文件，已全部补齐：

| 文件 | 补齐内容 |
| --- | --- |
| `/lib/netifd/proto/modemmanager.sh` | PDP 激活错误 28 的有界重试，保留既有 EPS/网络模式策略，不主动关闭射频 |
| `/etc/init.d/e5-board-identity` | 按可选板级元数据显示名称的公共服务代码，不植入 M8 型号 |
| `/usr/share/e5-infoscreen/api.uc` | USB 标准角色接口与 extcon/UDC 兼容读取 |
| `/usr/libexec/e5-voice-audio` | 屏幕 RPC 在等待音频 DSP 前启动，避免音频初始化拖住公共数据通道 |
| `/usr/libexec/e5-volume` | 冷播放预热根据音频路径选择，不再用机型白名单 |
| `/usr/libexec/unisoc-modem/cpu-control` | 最新电压能力识别和缓存版本；保留 T551M 的轨映射与既有设置 |
| `/opt/e5/e5-call-audio.py` | 公共听筒布线和音量曲线能力；T551M 没有 M8 专用元数据，仍使用本机听筒与原厂校准 |
| `/opt/e5/e5_call_profiles.py` | 配套音频能力模块；未配置衰减时直接保持本机原行为 |

| `/opt/e5/t551m-nv-prepare` | 启动阶段隔离副本双份恢复检查的最新版脚本；本次只更新代码，未执行准备/刷新或写入任何 NV 数据 |

## 验证

- profile、eMMC CID 核对确认 T551M；部署前检查没有通话。
- 所有文件先暂存、SHA256 校验、Python/Shell/ucode 语法检查，再替换；旧程序
  保存在主机 `out/t551m/full-sync-rollback.tar.gz`，不包含 NV 或用户媒体。
- 完成后核对 **212 个程序/资源文件，差异为 0**。包含已补丁的 hostapd、
  ModemManager wrapper、netifd 协议、LuCI 初始 EPS 选项和屏幕 ACL。
- **157 个内核模块**与最新主机构建清单一致；运行 Wi-Fi 模块 GNU build-id
  与最新修复版一致，boot_b 前 56 MiB 校验与最新 shared-fixes 镜像一致。
  其中已包含 F2FS 自动恢复修正和 Wi-Fi 公共修复，无需重复刷写内核。
- 全部现有 `/etc/config` 文件部署前后校验不变；未改默认启动、无线配置、
  电压/温控设置、用户音频或隔离/原始 NV 内容。
- 重启必要的音频和屏幕服务后，屏幕 API、实际提供的 JS、内核插拔事件订阅
  正常；WAN 一直在线，热点 ENABLED，音频服务无错误，CPU 三簇仍保留
  schedutil 和用户设置的 −12.5 mV，开机调压能力可读取。
- CPU 21 项、隔离副本 14 项、媒体音量 11 项、启动/重连 8 项、音频曲线
  4 项及通话状态/控制/音量回归通过；这些测试使用模拟文件/接口，没有拨打
  实际电话、制造 NV 故障或中断蜂窝网络。

此次补齐实机程序，未重打完整刷机包；一次性 uci-defaults 不因已经执行后删除
而被算成缺失，也未重放它们重置用户配置。没有开启后台日志采集。
所有公共功能走同一源码和构建入口；此前遗漏发生在按文件挑选的实机热更新，
后续应按完整依赖和预期文件清单核对，不能仅凭某一屏幕 JS 已是最新版推断
整个系统已同步。
