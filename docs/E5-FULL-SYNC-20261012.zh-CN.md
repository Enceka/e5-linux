# 荣悦 E5 全量同步与重启验证

确认 profile=e5、原有 eMMC CID、AW322 充电驱动和 mobile4 内核后，从当前
源码、公共 overlay 和 E5 stage 生成完整预期程序树，核对程序、屏幕、第三方
包内补丁、模块和 boot_b。

## 补齐内容

共更新 18 个程序文件：事件驱动插拔亮屏、USB 角色读取、看板请求隔离、热点
客户端指标、DFS 固定回退 36/保留带宽、屏幕 RPC 提前启动、公共媒体预热、
音频能力及配套模块、CPU 能力识别、AT 路由、隔离 NV 副本恢复脚本，以及
可选型号显示服务代码。PDP 错误 28 重连此前已存在，校验一致。

没有植入 M8 的听筒/喇叭布线、音量上限或衰减元数据；保留 E5 AW87xxx 功放、
原厂音频校准、充电和背光。仅更新隔离 NV 准备程序，未向原始 NV 分区写入。

另发现实机等待 vendor-ready 的启动检查已为 100 ms，而 stage 仍是 1 s。
公共 E5/M8 stage 现对齐已部署行为，保持约 12 s 等待上限，避免下次打包
增加启动延迟；这是启动阶段的有界等待，不是新增常驻后台轮询。

## 启动镜像与验证

原机仍用 mobile4-recovery。新镜像保持同一 E5 内核、模块加载顺序、其他
44 个启动模块和 init 不变；解包只发现以下两个变化：

- `linux-modules/sprd_wlan_combo.ko`：Wi-Fi 生命周期和日志修复。
- `etc/f2fs-repair.sh`：孤立节点可选导出询问的自动应答修正。

同步 TF 根内 Wi-Fi 模块及模块清单，boot_b 只写前 56 MiB，回读校验通过，
后 8 MiB 保持。没有修改 misc 启动选择；设备及主机均保存程序、模块、清单
和启动镜像头的回退副本。

重启后检查：

- 仍从原 TF 卡 ext4 根启动，默认 OpenWrt；userdata 保持原只读挂载。
  TF 启动继续跳过 F2FS 自动修复，没有强行检查/修复 userdata。
- 213 个程序/资源文件无差异，158 个模块校验一致；运行 Wi-Fi 模块 GNU
  build-id 和 boot_b 回读均匹配新构建。
- 屏幕 API、实际加载的 JS、屏幕服务和内核电源事件订阅正常。
- WAN 在线，热点 ENABLED 且保持 149 信道，CPU 和音频状态读取正常。
  蜂窝接口外网 ping 3/3 成功、平均约 58.6 ms。
- 所有原 `/etc/config` 文件在部署和重启后校验未变。

重启初期 Windows USB 网卡暂时保留链路本地地址。串口确认 E5 已正常启动、
LAN/DHCP 正常；仅对对应 USB 网卡续租后恢复 192.168.9.2 和 SSH。电脑未连接
设备热点，也未修改其他网卡设置。
