# 充电插拔事件唤醒与 M8 公共文件核对

## 原实现与修复

M8 原有 mobile.js 与仓库的 SHA256 一致，已经包含充电插拔亮屏逻辑。
并非没有移植：旧实现根据 `/api/status` 的 battery.online 变化唤醒，息屏
状态每 5 秒读取一次。一次断开、重连如果发生在两次读取之间，最终状态相同，
就不会触发唤醒；这能解释漏检路径，但尚未据此确认用户本次故障的全部原因。

公共 `e5_power_events.py` 现在订阅内核 NETLINK_KOBJECT_UEVENT，过滤
power_supply 事件，只接受内核发送者，识别 Mains、USB 系列和 Wireless
供电节点。Battery.online 表示电池存在，不能用来判断插充电器。
使用事件携带的 online 值保留已排队的短暂断开，不能只读已经恢复在线的 sysfs。
初始状态、重复事件及只有充满/电流变化的事件不唤醒。

借助屏幕已经使用的 WebSocket 发送供电变化通知，调用原屏幕唤醒路径，保留
锁屏、触控偏好和自动息屏计时。没有新增生产常驻进程、定时轮询或周期 flash
写入；现有状态轮询继续作为断连时的兜底。WebSocket 关闭时释放事件 socket。
监听运行于现有 `e5-voice-audio` 的屏幕 RPC 服务，更新 Python 文件后必须重启
该服务，单独重启 `e5-hfp` 不会重载它。

构建入口仍为公共 infoscreen stage，E5、T551M、M8 均安装同一实现。历史
目录名 t551m 不代表该功能限于 T551M；共享构建回归已补上 M8。

## 验证与部署

- 事件测试覆盖快速拔插、USB 转充电器、重复事件、Battery 过滤、非内核发送者。
- 真实浏览器覆盖事件到 WebSocket 到 JS 的通知，并验证无需状态轮询即可唤醒、
  保持锁屏；原充电状态变化不唤醒和主动关闭触控行为仍通过。
- 三个 profile 的打包检查及原持久连接、并发请求、断连兜底和关闭回收测试通过。
- M8 profile、eMMC CID 已核实，9 个运行文件部署及回读校验一致；浏览器实际
  获取的新 JS 校验一致，屏幕服务运行，RPC 进程内有内核电源事件订阅且无丢包。
- M8 离线根目录同步这 9 个文件。未重刷内核、未改 NV 或用户配置。
- 用户物理测试后反馈好用；按用户要求停止临时事件/背光采集，不继续抓日志。

## 公共文件核对范围

从当前共享 UI stage 生成预期文件，并补入实机 hostapd.uc 做公共补丁。
最终比较 138 个程序/资源文件，唯一差异是应保留的 M8 ADAPTATION 型号标记。
不比较用户 UCI 配置、用户媒体、已执行后删除的 uci-defaults、主题安装包缓存。

除事件唤醒的 4 个文件外，本次补齐了近期尚未部署的看板请求隔离、热点客户端
指标读取与后台补查，以及固定回退 36/保持带宽的 DFS 公共脚本和 hostapd 补丁。
没有为测试重启热点或改变当前信道。相关 RPC、指标补查及 ucode 策略回归通过。

这次是公共用户态文件核对，不代表所有机型的启动镜像、内核模块和完整刷机包
全部最新。此前 Wi-Fi 驱动修复与 F2FS 启动恢复修复仍需分别核对 M8 启动镜像。
回退文件、安装校验清单和检查结果保存在本地 `out/m8/charger-events-*`。
