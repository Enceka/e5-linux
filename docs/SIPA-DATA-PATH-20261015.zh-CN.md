# SIPA 短时停流：MU300 对比与公共修复

2026-10-15。按用户要求停止 T551M 临时采集，改为离线对比驱动，不要求复现。
电脑 USB 网卡保持用户设置的禁用状态；采集通过 COM77 停止，状态为 `stopped`。

## 结论的范围

群友报告 WAN 一直 up、TX 增长而 RX 停止约 6 秒，伴随 WWAN_DL 资源释放及
`sipa overflow on ep:1`。这些现象不能单独证明基带失效或需要重拨：

- TX 统计代表 SIPA 接受了包，不保证基带已发出或远端已回包。
- WWAN_DL 的 `2 -> 0` 本身可以是正常资源释放。
- `ep:1` 是 AP 端点，不是 SIM1。必须结合 `evt` 区分事件。
- 本机已有 `evt=0x10000`（TX FIFO 描述符错误）记录，出现时 WAN 仍连接；
  不能把每次这条日志都等同于一次用户可感知断网。

离线对比确认了下表中的代码缺陷。修复它们有明确依据，但本次没有复现群友那一次
中断，因此不能把任一项宣称为那次故障唯一、已经实测确认的根因。

## 与 MU300 的差异及处理

对比来源为本地 `mu300-linux-clean-tf-7.2/upstream/modules/sprd_modem`，
以及 E5 固定内核 `020b970e351e` 中的 `drivers/unisoc_platform/net`。
没有整套替换不同版本的驱动，保留 E5 的硬件配置和电源管理。

| 路径 | 确认的问题 | 本次处理 |
| --- | --- | --- |
| `sipa_eth_start_xmit` | E5 遇到 `-EAGAIN` 停队列后提前返回，跳过 `sipa_nic_trigger_flow_ctrl_work`；MU300 会执行恢复工作 | 停队列后仍安排恢复工作，并在同一个队列锁内检查资源流控，避免与唤醒交错 |
| `sipa_dele_local_rls_r_prod` | REQUEST 尚未完成就发 RELEASE，收到 REQUEST 应答后又发一次；MU300 等待应答 | 对齐 MU300，在应答后只发送一次 RELEASE；期间重新请求则保留授权 |
| CP 电源命令 | `pm_runtime_get_sync` 正返回值被当失败进入无限忙重试；重复 ENABLE/DISABLE 可累加或错减引用 | 使用 `pm_runtime_resume_and_get`；失败应答，不忙等；重复命令只重复应答，不重复操作电源引用 |
| CP 启动 | 在资源和 reset 工作队列就绪前启动收件线程；没有检查 start 结果；把依赖的 `-EINPROGRESS` 当失败 | 接受异步依赖；检查启动结果；先初始化 PM、锁、工作队列及资源，最后启动收件线程；失败时清理未运行线程和工作队列 |
| CP reset 与命令并发 | reset 使用的自旋锁不能保护没有使用该锁的电源命令 | 以可睡眠互斥锁串行化电源命令和 reset，保留 runtime PM、唤醒源和释放逻辑 |
| 发送完成回收 | 一个 DMA 地址匹配失败就退出，却仍整批推进 FIFO；后续有效完成项对应的 skb 和额度未回收 | 参考 MU300 的逐项处理，坏项不阻断后续回收；额度只按实际释放数归还；取不到节点时只推进已处理前缀 |
| 发送重试 | 返回 `NETDEV_TX_BUSY` 前压入的头部没有恢复，重复尝试可能再次压头；此风险 MU300 的对应旧代码也有 | BUSY 前恢复 skb 的头部和长度；已经释放的 skb 返回 `NETDEV_TX_OK`；正常背压不计作实际丢包 |

电源问题需区分硬件分支：`sipa_sys_eb=0` 不调用 runtime PM 恢复函数，仍会受到
重复 ENABLE 的 SIPA 引用问题影响。不能把另一分支的忙重试直接当作本机断网证据。

上述代码位于 `devices/common/sipa-data-path.patch`，由 `devices/common/sipa.py`
整体验证后应用。E5、T551M、M8 和两个通用 mainline 构建入口均接入；不是仅对
某台机器修补工作目录。与支持版本不一致的源码直接拒绝，避免部分补丁静默漏掉。

没有改 AT、SFUN、拨号或开机回放时序，没有增加 watchdog、联网探测或后台轮询，
没有禁用 SIPA 的正常省电机制。本次没有修改 MU300 仓库，也没有刷入新内核。

## 屏幕 NR 频段与网页

实机同一 SIM 的候选项对照一致：LTE 为 B1/B3/B5/B8/B34/B39/B40/B41，NR 为
n1/n5/n8/n28/n41/n78。NR 仍从基带能力动态获得，不写死本次六个值。

确认的界面差异：屏幕编辑器会沿用进入网络设置页时的快照，网页更新后仍可能看到
旧选择；全部支持频段启用时，网页显示自动，屏幕原来逐一列出。
现在进入频段编辑器重新读取共享缓存，失败不打开旧编辑器，离开页面后的迟到应答
不再弹回编辑器；自动模式与网页一致。状态摘要保留实际回读，不把不在候选列表
中的原始掩码位混入可提交的选择。没有额外轮询 AT，也没有写入任何频段设置。
