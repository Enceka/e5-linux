# 双卡长短信接收修复

从 `D:\Git\mu300-linux-clean-tf-7.2` 当前工作区的长短信修复同步规则。
MU300 使用 shell/AWK；本仓库使用 Python PDU 解码和双卡持久化收件箱，
因此同步的是分组、持久化和发布规则，不覆盖不同的收信实现。

公共文件为 `openwrt/overlay/usr/lib/e5/sms_pdu.py` 和
`openwrt/overlay/usr/libexec/e5-sms-receive`，E5、T551M、M8 共用。

## 修复内容

- 按 SIM 身份、发送人、8/16 位分段参考号、总段数、DCS、PID、SMSC 和其他
  UDH 元素区分分组。以网络 SCTS 相差不超过 10 分钟约束参考号复用。
- 严格按段序号拼接。重复 PDU 不增加段数，不重复发布短信。
- 缺段原始 PDU、存储索引、首次接收时间和历史来源写入同一原子持久化
  `inbox.json` 的 `pending` 字段；空扫描和进程重启不清除缺段。
- 收齐前不分配消息 ID、不在网页或屏幕显示、不响提示音、不触发转发。
  完整短信与分段移除在同一次原子保存中提交，重复投递不会再次入库。
- 删除记录保留分段指纹，重投不会让已删除的短信复活。
- 任一分段来自首次历史同步，完成后仍按历史短信处理，不误发提示或转发。
- 两个候选组无法区分时保留原始分段，不猜测、不串接、不覆盖。
- 旧 `receiving` 记录有完整原始 PDU 时迁入缺段区；已经完整的历史短信
  不重写。缺少 PDU 的旧半条记录隐藏，但不根据文字和时间猜测拼接。

本仓库已有 PDU 收取路径，没有 MU300 的文本模式“发送人 + 同一秒”拼接。
继续保留原有 ModemManager AT 所有权、双卡来源、事件通知和轮询频率，
不切上网卡、不重连网络、不新增服务或轮询。
