# Android / TF 安装启动链同步（2026-10-12）

> 2026-10-14 更新：下文 TF 预留空间/重建 GPT/双根更新描述为旧版流程。新版使用已有第一分区（无分区则整卡）的全部容量，更新统一走电脑安装器；见 [TF-SINGLE-ROOT-20261014.zh-CN.md](TF-SINGLE-ROOT-20261014.zh-CN.md)。

参考本地 `mu300-linux-clean-tf-7.2/tools/android-bootchain.sh` 的 OTA 兼容方案，
在本仓库增加公共 `tools/android-bootchain.sh`。Android OTA 后两槽启动链可能
不同；Linux 运行当前 Android 的厂商程序时，不应未经检查继续使用另一槽的旧链。
这是一项兼容性修复，不表示所有启动或基带故障都由启动链差异导致。

## 共用入口

- 电脑安装器：TF 首次安装、userdata 首次安装、`--boot-openwrt`。
- Magisk 切回模块 1.1.0：`check` 只检查；点击「操作」同步后再切槽重启。
- `openwrt/make-flash-bundle.sh` 和 `magisk/build.sh` 从同一源文件打包，
  发布检查核对内容，避免两个安装入口的修复不同步。

## 写入顺序与范围

1. 要求已 root、解锁的 Android A；校验当前 misc BCAB v1、双槽、CRC、
   A 成功启动标记、verity 状态。B 优先级高于 A 时按待完成 OTA 拒绝。
2. 对 `uboot/sml/teecfg/trustos/vbmeta` 检查两槽块设备、容量、哈希和别名。
   拒绝重叠或指向非目标分区的别名。启动链操作使用公共互斥锁。
3. 仅对有差异的项，先保存 A、B 两份镜像、路径和 SHA-256 到
   `/data/adb/e5-bootchain/<唯一目录>/`；全部备份验证成功并刷盘后才开始写 B。
   再检查源内容和 misc 未变化，避免准备期间的变更。
4. 写入 B 后刷盘、刷新块缓存并回读；失败或可处理的中断信号触发回滚，
   包括已经写过的项和正在失败的项。回滚失败返回单独状态、显示备份位置，
   不继续切槽或重启。相同项不会重写。
5. 电脑安装器不再要求 misc 与打包设备逐字节相同；从本机有效控制块生成
   B 槽两次试启动信息，备份在 `/data/adb/e5-boot-control/`，只改偏移 2048
   的 32 字节，校验失败尝试恢复。

启动链工具不写当前 Android A，也不读写 NV、校准、modem、boot 或 userdata
原始分区；其备份是 Android data 文件系统中的普通文件。安装器自身仍需写
TF、boot_b、启动选择文件和 misc。Magisk 切回模块不重装系统、不写 boot。

强制断电、SIGKILL 或硬件写故障不能由 shell 保证自动恢复；备份持久保留，
已开始同步时不要断电。中断遗留锁需要先核查，没有自动抢锁或强制继续的路径。
这不是跨五个分区的断电原子事务，也不能替代 OTA 服务本身的互斥机制。

## TF 首装同步改善

- 启动镜像大小、两槽启动链在清卡之前预检。
- 本机固件提取、转换和镜像上传全部提前，失败时不会先清卡。
- 先请求 Android 释放卡，再检查当前及 init 挂载命名空间中的设备号。
  挂载残留直接停止；不使用强制卸载或懒卸载。
- 写入系统和固件后生成固件 SHA-256，卸载、刷新缓存、只读 `noload` 重挂，
  检查关键文件和固件哈希，通过后才写 boot_b，最后设置 misc。
- 首次安装完成后手动重启；显式 `--boot-openwrt`、Magisk「操作」及更新仍会重启。

## 保留的本仓库设计

这次是选择性适配，没有引入完整 Magisk TF 首装模块。它仍是电脑首次安装、
Magisk 日常切回。

- Android A / Linux B 保留。启动回退、基带固件与厂商程序路径依赖该约定，
  不能仅修改安装器就支持 Android B / Linux A。
- TF 继续使用镜像写入及 GPT 预留空间，供另一系统分区更新、试启动回退及多系统。
  没有改为全容量第一分区或裸卡 ext4；那需要同时设计新的更新/回退机制。
- 当前写入的是已有 ext4 镜像，没有调用 Android mke2fs，因此不照搬其格式化参数。
- 没改首次账号密码策略，也没新增 Android 热点配置导入。
