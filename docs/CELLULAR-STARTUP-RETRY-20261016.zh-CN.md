# 首次蜂窝连接失败后的自动恢复（2026-10-16）

> 下文前半部分是最初的定时退避记录。后续已对照 E5 原厂 telephony DEX，增加 PS
> 注册／RAT 事件恢复，修正无覆盖时 netifd 丢失 autostart 的问题。
> 原厂证据、当前行为与实机结果见
> [原厂对照与省电修复报告](STOCK-POWER-RECOVERY-20261016.zh-CN.md)。
> 当前可重试拨号失败按用户选择的 1→3→5→7 秒循环，不设次数上限。
> 无覆盖时继续由既有 PS 注册事件恢复，未改成循环主动搜网。
> 这些等待间隔不是声称从原厂逆向还原的运营商精确时间表。

E5、T551M、M8 共用 ModemManager/netifd 拨号流程。之前只针对 PDP 错误 28 最多尝试三次；
注册超时、无网络和暂未读到 IP 等失败可进入 proto_block_restart，之后即使信号恢复也不再自动拨号。
连接成功后才启动的移动地址监视器不能补救这个首次连接缺口。

## 本次处理

- 网络注册和 simple-connect 共用临时错误白名单：无网络、注册／AT 超时、无载波、临时忙／重试、暂缺 IPv4，以及既有 PDP 错误 28。
- 可重试失败后按 1、3、5、7 秒等待，之后从 1 秒开始重复，无次数上限；等待从上一轮命令返回失败后开始，命令串行执行，单次 mmcli 的 120 秒超时保持不变。
- 无覆盖／PS detached 仍走之前对齐原厂的注册事件恢复，不用这个短周期循环替代无信号机制。
- SIM/PIN/PUK、鉴权、错误 APN 参数、不支持的配置、错误状态及未识别错误不进入这个循环，保留现有报错／阻止自动重启的流程。
- 重试只存在于当前 netifd setup 中。取消 setup 的 SIGTERM/INT 会终止正在运行的 mmcli 或等待子进程、清理临时文件并退出，不执行后续拨号。
- 不添加独立常驻轮询，不修改 WAN 自动启动配置，不在已连接状态新增探测。
- 不添加 SFUN/CFUN、切卡或 modem 禁用／启用命令。开机回放、APN 选择、初始 EPS 和网络模式仍按原位置执行；重试范围仅包围原注册／拨号命令。
- 仅对 device=unisoc-sipc 生效，其他 ModemManager 插件仍单次调用。
- stager 会更新已存在的旧版错误 28 有限重试函数，重复应用保持幂等；APN 和回放钩子不重复插入。
- ModemManager 包修订号增加，APK 升级包含同一份公共网络 stager 修改。

取消机制与 netifd 的 [setup/teardown 状态机](https://github.com/openwrt/netifd/blob/master/proto-ext.c) 对齐；
本地行为测试直接向 BusyBox ash 的 setup 进程发送 SIGTERM，而非只测试终止整个进程组。

## 验证范围

公共启动回归覆盖所有三种 profile、旧脚本升级、重复应用、连续三轮 1/3/5/7 循环、注册失败后恢复、暂缺 IPv4 后恢复、永久错误不重试，
以及停止正在执行的命令和正在等待的重试时子进程退出、临时文件清理。
该测试使用受控 mmcli 回复，没有在真实弱信号环境复现，因此不把它视为所有网络故障都已排除。
不改动现有外场地址续租监视器及其 AT 请求顺序。

最初构建：`out/openwrt/modemmanager-1.24.0-r932.apk` 与配套 RPCD APK。
从实际 APK 解包所得协议脚本重复通过 11 项启动回归；原有地址续租和 7 项端口发现回归、编译流程内短信／通话／移动性检查均通过。
初版当时未部署。后续 r933 构建完成，公共脚本与事件服务已部署到 E5，8 项事件恢复测试、
12 项启动回归通过；受控实机恢复约 8.04 秒，手动断网保持关闭。整机发布包尚未重新生成。
