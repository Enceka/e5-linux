# TF / userdata 分区安装流程审计（2026-10-13）

> 2026-10-14 更新：下文 TF 预留空间/重建 GPT/双根更新描述为旧版流程。新版使用已有第一分区（无分区则整卡）的全部容量，更新统一走电脑安装器；见 [TF-SINGLE-ROOT-20261014.zh-CN.md](TF-SINGLE-ROOT-20261014.zh-CN.md)。

本轮检查公共脚本并做离线验证，适用于 E5、T551M、M8。没有格式化或修改
连接设备的分区，没有把尚未重打包的修复称为现有发布 ZIP 已包含。

## 当前流程与约束

| 路径 | 顺序 | 容量与数据 |
| --- | --- | --- |
| TF 首装 | 校验包/机型/启动链 → 提取本机固件、上传载荷 → 释放 Android 卡挂载 → 备份同步 B 槽启动链 → 整卡 GPT 重分区、写根镜像 → 镜像与固件回读 → 写 boot_b → 记录目标、设置 B 试启动 | 清空整张卡；根分区按约 2 GiB 镜像分配，其余留作更新/后续分区；不是保留现有第一分区的安装器 |
| 未加密 userdata | Android 上记录计划和载荷 → initramfs 校验载荷 → 离线检查/缩容 F2FS → 验证缩容 → 缩小 GPT userdata、创建 e5root → 写镜像、回读、按选择扩容 → 导入固件/设置 → 重置试启动次数后重启 | 保留 Android 文件；只有选择“完全使用空间”或 `--grow-fs` 才把文件系统扩满分区 |
| 加密 userdata / 明确选择格式化 | 电脑保存事务及备份 → initramfs 检查 CID/几何/未挂载/无 holder → 重建 GPT 并写准备标记 → 回原厂 recovery 清空 data → 用户重新设置 Android/ADB/root → 电脑核对身份和分区 → 写 e5root、扩容、回读 → 刷 boot_b、设置 B 试启动 | 不依赖解密旧 data，也不在将被清空的 data 中保存 OpenWrt 载荷；需要保留电脑上的事务目录 |

当前安装器要求 **Android A / OpenWrt B**。Android 在 B 时先拒绝，不支持
自动反向安装。TF 和普通首装结束后手动重启；加密两阶段第一阶段会自动
重启，等待 recovery 和 Android 授权后续装，最终安装仍手动重启。

加密自动检测会改变路径，但不代替清空授权；无人值守必须明确传入
`--format-userdata`。两阶段完成后的 Android 可能重新加密 data，不影响
独立 e5root 启动。原厂 recovery 的自动清空与首次设置需逐机型实测。

## 本轮补齐

1. 未加密流程原来先缩容/改变 GPT，才检查 gzip。改成启动心跳后先检查
   根镜像和固件归档、解压尺寸；缺失、损坏或超出分区就停止写入流程。
2. 原来 `resize.f2fs` 退出失败但超级块已有目标尺寸时，仍可能进入 GPT。
   现在必须退出成功，再运行 fsck、核对尺寸后才缩短分区；已经缩过的重试
   也执行一致性检查。记录检查/缩容日志到现有启动持久日志。
3. TF 与旧缩容路径补齐完整根镜像 SHA256 回读，发生错误不进入后续提交。
   TF 刷新块缓存后验证原始镜像，再写本机设置；旧路径在扩容/导入前核对镜像。
   校验会增加安装耗时，界面继续显示阶段与经过时间，不影响正常开机。
4. 两阶段 Android 写入路径在卸载后刷新块缓存、只读重挂并校验所有固件、
   vendor 文件和关键标记；设置文件权限为 0600。工具目录创建失败也会释放
   本次取得的安装锁，不留下无法继续的空锁。
5. Windows 默认 GBK 环境可能把中文 SSID 写成 GBK。TF、userdata 镜像和
   保数据缩容的设置文件均明确 UTF-8；加密续装原来已使用 UTF-8。
6. 同步重建 Windows `flash.exe`，避免 Windows 优先执行旧程序。旧 ZIP 和
   旧 boot.img 不会随源码自动变化，需在下一轮打包重新构建。
7. 覆盖重装/加密续装补齐公共 boot 大小、BCAB、启动链预检查，提交 boot
   前再同步启动链，避免 Android OTA 后续装仍沿用旧 B 槽 BSP。同步失败
   保留 installed 事务阶段，不刷 boot、不切槽，后续可重试。

## 用户入口与打包联动

按用户要求，包内 exe 和脚本入口全部使用英文语义名称。统一入口为
`OpenWrt-Installer.exe` 或 `start-installer.cmd/sh`，无参数时显示双语方式
选择菜单；TF、内置安装、覆盖重装、续装、切回、更新各有独立入口。
内部两阶段实现移入 `scripts/installer`，不会出现在根目录与用户入口混淆。

三款 profile 打包与 CI 的通用打包共用同一个入口生成器，校验清单也覆盖
所有入口。Windows exe 的二进制/源码指纹同时校验，旧 exe 会阻止打包；
可用 `python tools/build-flash-exe.py` 在 Windows 重建。Windows 启动器保留
引擎的退出码，不再被 pause 或括号中的提前变量展开掩盖。

新增 3 项菜单/入口回归，在 Windows cmd 和 Linux sh 各执行一次，验证
带空格的安装目录、SSID 参数、事务路径和失败退出码；另 11 项 CI 校验
回归通过。原 CLI 选项仍兼容，源码中的旧开发文件名不必改动。

## 验证

53 项 Python/shell 回归通过：安装失败诊断、试启动控制写入、保数据缩容
失败保护、两阶段恢复、真实 2 GiB → 10 GiB ext4 扩容、分区根发现与 F2FS
修复回归。另有 10 组真实稀疏 GPT 计划/修改测试通过，未操作实机磁盘。

新测试执行实际 shell 分支，使用临时文件和模拟裸工具验证：损坏载荷不会
调用 fsck/resize/GPT；退出失败但尺寸改变不算缩容成功；复查失败不改 GPT；
短写/损坏镜像不通过完整哈希；卸载后的固件损坏不能通过只读回读；工具
创建失败释放锁；根验证或 boot 写入失败不把事务推进到 complete。
TF 中文配置在模拟 GBK 默认编码下仍为 UTF-8。

这些验证覆盖实现和失败分支，不替代三款原厂 recovery 的完整加密安装
验证，也不保证在实际断电、卡故障或 F2FS 自身失败时可以无损完成缩容。
没有自动还原 GPT 到原尺寸：文件系统已缩过或新分区已写入时，盲目恢复
旧分区表可能覆盖有效数据；保留诊断与备份，按实际阶段恢复。
