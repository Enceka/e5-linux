# Issue 修复扩散验证

日期：2026-10-17。范围为本轮 E5 公共 issue 修复及工作区中关联的锁频段变更。
只在本地临时文件、模拟 API、已有内核源码和隔离的安装目录中验证；未部署、刷机、写 NV 或修改已有发布包。

## 找到并修正的三个问题

### 1. 旧密码套件被隐藏后可能自动变成 auto

原 LuCI `ui.Select` 使用原生 HTML select。当配置保存为 `sae+gcmp`，而筛选后的候选列表没有 `gcmp`，浏览器会选中第一个 `auto` 选项。即使用户只想改热点名称，也可能改变密码套件。

修正：只为当前已保存的不支持值保留一个标记为 Unsupported 的选项，保持原值；验证器仍明确拒绝它，用户必须主动选择支持的套件。新配置不会额外获得这些不支持的候选项，其他无线芯片按其实际能力筛选。

验证直接提取实际 pinned LuCI 的 `ui.Select` 代码在 Chromium 中渲染：旧行为选中 `auto`，修正后保持 `gcmp` 并返回校验错误。另验证 CCMP/GCMP/CCMP-256、多无线芯片能力差异、能力未知、重复读取和重复应用。

### 2. 连续唤醒可能丢失最新刷新

原实现用一个正在执行的 Promise 防止重复请求；若第一次请求还未完成就再次息屏、亮屏，第二次刷新会被丢弃。第一份过期快照可能显示到页面上。

修正：按唤醒事件更新请求代次。正在执行的旧请求结束后，仅最新一次仍可见的唤醒追加一次读取；旧代次响应不绘制。不增加常驻轮询。离开页面、锁屏和未提交的编辑器仍受保护。

新增可控慢响应浏览器测试，先复现旧实现缺少第二次请求，再验证最新状态、隐藏页面不回写、编辑内容保留。既有加载反馈、通话、APN 和屏幕整体流程也重新通过。

### 3. 原生 TF 安装缺少新工具依赖的前置检查

新的扩容校验依赖工具归档中的 `ext4-geometry.sh`。电脑打包入口已检查旧归档，但原生 TF 安装的 preflight 未检查这一成员；不完整归档可能到写卡后才失败。

修正：加入原生 TF preflight 的必需成员列表，在卡释放、格式化、写入和切槽前拒绝缺失归档。新增测试执行实际安装脚本的 preflight，使用临时包和模拟块节点，确认缺少成员时不会进入后续启动链检查。未访问真实分区。

## 扩散验证结果

- **19 组主回归通过**：其中 unittest 统计 191 项，另有充电 profile 的实际 C 代码测试。覆盖屏幕电源、充电策略、普通/关机充电启动、开机回放、AT 路由、锁频段与重连、原始 netifd/EPS 分支、安装续装、镜像扩容、旧设置更新兼容和菜单入口。
- **浏览器流程通过**：完整屏幕、充电插拔亮屏、设置同步、延迟/失败加载反馈、电话、屏幕 APN、新增连续唤醒竞态，以及实际 LuCI select。屏幕整体回归的 JS 异常为 0。
- **三机型回调验证通过**：分别对 E5、M8、T551M 已适配源码编译执行实际 SD/充电回调的模拟测试。新增 VMMC 成功但 VQMMC 失败后的重试、pinctrl 失败、空卡槽和非 TF 路径重复调用检查。没有改动内核实现来迎合测试。
- **三机型公共文件落地验证通过**：对 `ui.stage(..., profile=...)` 实际执行临时目录安装和重复应用，核验 helper、ACL、首次启动 hook、文件执行权限及 LuCI 幂等补丁；没有向运行设备推送文件。
- **Wi-Fi 套件 4 项与原生 TF 前置检查 1 项通过**，包含上述真实控件和缺失依赖复现。
- `git diff --check` 通过。

本地详细日志位于忽略目录 `work/issues-side-effects-20261017/`；`regress.json`、`browsers.json`、`browser-extended.json` 保存执行结果。最初网络启动测试缺少必需的原始协议/UI fixture 参数，补齐参数后 15 项通过；这不是产品运行故障。

## 仍不能由本轮验证证明的事项

- 特定 TF 卡的 UHS 电气切换是否恢复，需要对应机器和卡实测；寄存器回读不是管脚电压测量。
- SIPA hung-task 的原始调用栈仍缺失，不能把充电属性修正当作卡死根因已解决。
- KSU/KSUNext 原生模块安装只做了工具路径、安装流程和失败分支验证，尚无对应管理器的实刷结果。
- 没有宣称验证真实续航、蜂窝搜网时间、通话听感，或完成了新一轮整套内核发布编译。
